# Content snapshot scope

The starting table allowlist is the72tables defined by the original retained PEQcontent member, listed in ../coverage/snapshot-scope.json. New feature tables require exact names, columns and intended row filters from owner migrations before inclusion. Default is deny. `spawn_conditions` and other mutable defaults require an explicit intended-content policy rather than current transient values.

Rows must represent baseline content plus intended applied deltas, excluding QA-only definitions and private customization. Table membership in content_db does not establish public suitability. NPC/merchant/item/recipe/reward rows need their owning-feature source provenance; dependency code/script versions and migration order are recorded separately. Split deployments must guard runtime custody on the actual runtime connection; content snapshot emptiness cannot prove custody safety.

No accounts, characters, inventory, object_contents/world-container custody, owned mercenaries, fellowship memberships/XP, housing ownership/placeditems/escrow, shroud snapshots/sessions/banks/progression, credentials, logs or temporary QA fixtures are in scope. SchemaDDL for those runtime systems can be published as our own migrations without exporting their populated rows.

No snapshot is generated by this document. Full downloadable SQL content releases follow only after explicit extension table/column/row scope and version composition are assembled. Original archive redistribution terms remain an independent limitation; they do not prevent publication of our own existing SQL updates.
