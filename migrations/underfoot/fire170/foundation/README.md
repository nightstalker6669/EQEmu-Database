# Fire170 foundation source helper

This source package does not install or activate anything. It contains the three byte-exact published R17 disabled CREATE statements and a finite installer/verifier/empty-only recovery helper. Python3 and PyMySQL are required. Default invocation only describes the selected phase without a database connection. No build, test, runtime action or SQL execution was performed in preparing it.

`foundation.py --phase install_or_verify` checks all three pre-existing schemas before the first CREATE. It creates absent tables one at a time, or verifies an already exact table without changing it. A pre-existing exact nonempty table may be verified and is preserved; the separate release helper still refuses activation against existing custody/history. Unknown columns, defaults, indexes, CHECK predicates, engine/collation overrides, triggers, foreign keys or partitioning stop the operation. It never ALTERs or silently adopts incompatible definitions.

MariaDB DDL implicitly commits. There is deliberately no BEGIN/COMMIT wrapper or atomic multi-table claim. Each table has its own durable absent preimage/create intent and independent fresh-connection schema/empty verification receipt. A failure stops immediately, preserving earlier completed CREATE receipts and any uncertain table; it does not retry or run an inverse. A fresh explicit authority is required to continue after operator disposition.

`--phase verify` requires all three exact schemas and writes only local verification receipts. All actual phases require --execute, exact config and authority SHA256, pinned publication and helper manifest, coordinator admission/writer hold, actual database identity, and a fresh receipt directory. One-use authority markers and receipts must remain with this exact helper installation. No real authority is included; AUTHORITY-TEMPLATE.json grants none.

`--phase recover_empty_owned` requires separate explicit authority and the pinned earlier terminal installation receipt. Only tables positively recorded as created and independently empty by that installation are eligible; pre-existing tables are never dropped. A partial failed installation may release only its positively completed created tables. An uncertain CREATE with no completed receipt stays held. Recovery verifies all selected schemas, exact SHOW CREATE hashes and empty counts before the first drop, refuses incoming foreign-key consumers, and rechecks under a table WRITE lock before each DROP. Each DROP is individually receipted and independently verified absent. Any nonempty/changed/unknown table stops recovery; no custody, player or history rows are deleted or restored.

The complete successful installer final-receipt.private.json is the `foundation_install_receipt` dependency accepted by the separate254-row release helper. It does not itself authorize staging or activation. The three foundation names must then exist and have zero rows for that helper's activation guard. No seventeen-table recapture, migration version assignment, backfill, admission flag, persistent chest/condition row, or gameplay acceptance is included.
